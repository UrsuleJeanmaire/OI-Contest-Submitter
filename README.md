# Submitter - 信息学竞赛提交管理工具

## 项目介绍

**Submitter** 是一款专为信息学竞赛（IOI 赛制）设计的**离线提交管理工具**，适用于**机房离线环境**（不依赖互联网或在线评测系统）。它通过在局域网内共享文件夹（如 Windows 网络驱动器）来模拟 OJ 的提交、存储与评测流程，帮助教师或学生在无网络条件下高效管理代码提交、自动记录、评测结果追踪等任务。

该工具完全基于 **.NET Framework / .NET Core** 编写，以控制台界面交互，轻量、稳定，适合在机房批量部署使用。

---

## 功能特性

- **多比赛管理**：支持同时管理多个比赛，可随时切换或退出当前比赛。
- **自动拉取比赛结构**：`join` 命令可自动下载比赛文件夹下的所有题目目录及配套文件（数据、题解等），并保留完整目录层级。
- **代码提交与哈希标识**：提交代码时根据用户名、题目名、提交序号自动生成短哈希（SHA256 Base64 缩短版）作为唯一记录 ID，避免重名冲突。
- **提交记录持久化**：每次提交生成 `.rec` 记录文件，包含提交者、题目、时间、评测结果链接等信息，便于追溯。
- **评测辅助功能**：`starttest` / `singletest` 命令可将待测代码复制到剪贴板，方便粘贴至本地评测环境（如标准输入输出测试），评测完成后输入结果链接即可完成记录。
- **灵活的结果查看**：`check` 命令可打开评测结果链接（如本地 HTML 报告），`records` / `allrecords` 分别列出个人或全体提交记录及评测状态。
- **断点续传/重试**：`redownload` 命令可重新尝试下载因文件占用等原因失败的文件，最多重试 10 次，确保比赛资源完整。
- **日志系统**：所有操作记录写入 `log.txt`，便于排错和审计。
- **配置持久化**：服务器地址、账户、密码、用户名、本地保存路径保存在 `setting.ini` 中，下次启动自动读取。

## 使用方法

### 环境准备

- 操作系统：Windows（依赖 `net use` 命令映射网络驱动器）。
- 共享文件夹：在局域网内设置一个可读写的共享目录（作为“服务器端”），确保客户端具有访问权限。
- 运行环境：.NET Framework 4.6+ 或 .NET Core 3.1+（编译为可执行文件即可）。

### 快速开始

1. 编译或直接运行 `Submitter.exe`。
2. 首次启动会提示输入配置信息：
   - 服务器文件夹地址（例如 `\\server\share\contests`）
   - 服务器账号（域账号或本地账号）
   - 服务器密码
   - 你的名字（用于标识提交者）
   - 下载文件的保存路径（本地文件夹）
3. 配置完成后进入主交互界面，支持以下命令（输入 `help` 查看完整列表）：

| 命令 | 说明 |
|------|------|
| `help` | 显示帮助文本 |
| `join <比赛名>` | 加入指定比赛，并下载该比赛的所有文件夹结构及文件 |
| `redownload` | 重试下载之前未成功的文件 |
| `submit <题目名> <文件路径>` | 将指定代码文件提交到当前比赛的指定题目 |
| `check <记录ID>` | 查看指定提交记录的评测结果（如果已评测） |
| `records` | 列出当前比赛下自己所有的提交记录 |
| `allrecords` | （教师/评测机）列出当前比赛下所有用户的提交记录 |
| `quitmatch` | 退出当前比赛 |
| `reset` | 重新进行参数设置 |
| `starttest` | （教师/评测机）开始批量评测所有未评测的提交（逐个复制代码到剪贴板） |
| `singletest <记录ID>` | （教师/评测机）单独评测某条提交记录 |
| `quit` | 退出程序 |

### 典型工作流（学生）

1. 运行程序，设置配置（若首次）。
2. 执行 `join ICPC2026` 下载比赛资源。
3. 编写代码后，执行 `submit A C:\work\a.cpp` 提交题目 A 的代码。
4. 系统返回记录 ID（如 `abc12345`），并自动将该记录加入待评测队列（教师端处理）。
5. 教师执行 `starttest` 或 `singletest abc12345` 后，代码被复制到剪贴板，教师可粘贴至本地评测器运行，并在提示后输入结果链接（如 `file:///C:/result.html`）。
6. 学生执行 `check abc12345` 即可打开评测结果链接。

### 典型工作流（教师/评测机）

1. 同学生步骤加入比赛。
2. 所有学生提交后，执行 `starttest`，程序会依次将未评测的代码复制到剪贴板，教师逐个评测并输入结果链接。
3. 若需重测某条，可使用 `singletest <记录ID>`。

## 代码组织架构

项目采用分层模块化设计，按功能划分命名空间，结构清晰，便于维护和扩展。

```
Submitter/
├── Program.cs                 # 程序入口，初始化日志并启动主管理器
├── Constant.cs                # 常量定义（配置文件路径、日志路径）
├── Hash.cs                    # SHA256 短哈希生成工具
├── Code/
│   ├── Component/             # 通用组件
│   │   ├── Displayer.cs       # 彩色控制台输出封装
│   │   ├── Log.cs             # 日志记录（文件写入，自动轮转）
│   │   ├── FileFinder.cs      # 递归搜索文件/目录（服务器路径）
│   │   └── Tester.cs          # 评测辅助（剪贴板操作，评测流程控制）
│   ├── Manager/               # 管理类（核心业务）
│   │   ├── MainManager.cs     # 主循环，命令解析与分发
│   │   ├── FileManager.cs     # 文件/网络管理（配置加载、net use 连接、上传下载）
│   │   └── IOManager.cs       # 基础文件读写（UTF-8 编码，行读写）
│   ├── Command/               # 具体命令实现
│   │   ├── JoinCompetition.cs # 加入比赛，下载结构，重试机制
│   │   ├── SubmitCode.cs      # 提交代码，生成记录文件，加入待评测队列
│   │   └── ShowRecords.cs     # 显示个人或全部提交记录
│   ├── Data/                  # 数据结构
│   │   └── Record.cs          # 提交记录实体（解析 .rec 文件）
│   └── Ability/               # 辅助功能
│       ├── IsEvaluation.cs    # 判断记录是否已评测
│       └── RemoveLastLine.cs  # 删除文件最后一行（用于覆盖评测链接）
```

### 核心模块说明

- **MainManager**：程序的总控，循环接收用户输入，匹配命令并调用相应处理类。
- **FileManager**：负责与共享文件夹的所有交互，包括 `net use` 网络连接、文件上传/下载、目录操作，以及配置的保存与加载。
- **JoinCompetition**：递归遍历比赛目录，在本地创建镜像结构，并尝试下载所有非 `#submit` 目录的文件。
- **SubmitCode**：根据当前用户名、题目名和提交次数生成哈希 ID，将代码复制到服务器指定位置，并创建 `.rec` 记录文件和更新待评测列表。
- **Tester**：利用 Windows API 将代码内容复制到剪贴板，供评测机快速粘贴；评测完成后将用户输入的链接追加到 `.rec` 文件中。
- **FileFinder**：在服务器目录中递归查找特定文件（如 `.cpp` 或 `.rec`），返回其完整路径或内容。
- **Record**：负责解析 `.rec` 文件，提供键值对访问（id, problem, submitter, time, result）。

## 依赖与注意事项

- 依赖 Windows `net use` 命令进行网络驱动器认证，因此**仅支持 Windows 环境**。
- 服务器共享文件夹需对客户端开放读写权限。
- 所有路径使用反斜杠 `\`，注意转义。
- 日志文件 `log.txt` 超过 500KB 会自动清空，防止无限增长。
- 评测结果链接可以是任意可访问路径（本地文件、网络路径等），`check` 命令会调用系统默认程序打开。
